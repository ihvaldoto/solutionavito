# Детекция ботов — описание решения

**Итог:** P@R≥0.7 = **0.8901** на скрытом тесте (константа: 0.0939).
**Python:** 3.12. **Библиотеки:** pandas, numpy, scikit-learn, LightGBM (open-source, локально). LLM и внешние API в решении не используются.
**Запуск:** `python solution_v4.py` → `submission.csv` (seed = 42, результат воспроизводим).

## Обработка данных
- Удалено 4863 полных дубликата событий.
- В признаки идут только события внутри окна `window_start_ts <= event_ts < window_end_ts`. Это важно: 17% событий кук трейна лежат вне окна.
- События сортируются по времени внутри куки. Все признаки приводятся к float.
- Пропуски: для кук без событий счётчик = 0, остальные признаки NaN (LightGBM обрабатывает их нативно). Пропуски в данных в основном структурные: у поиска нет `item_id`, у просмотра нет `search_query`. Случайные пропуски (категория, тип продавца) одинаковы у ботов и людей, сигнала не несут.
- Категориальные поля не подаются как сырые метки: из них считаются доли и число уникальных значений. `platform` записан в 11 вариантах регистра для 3 платформ, а `user_agent` почти не отличает ботов (даже у headless и curl доля ботов только 20–50%).

## Признаки
1. **Ритм действий:** медиана, минимум, квантили интервалов между событиями и т.д. Боты работают пачками по 6–10 действий с интервалом 3–20 с.
2. **Широта обхода и последовательность:** число объявлений, категорий, локаций, глубина выдачи, переходы между событиями, возвраты к объявлениям, контакты на объявление.
3. **Геометрия курсора (v3):** доля событий с курсором ровно на краю экрана (x = 0 / ≥1920, y = 0 / ≥1080), максимум и среднее координат. У людей курсор не достигает краёв и ходит по всему экрану, у ботов он в узкой зоне и «обрезается» по границам.
4. **«Толпа» вокруг объявлений (v4):** парсеры обходят общий пул объявлений.
   - `ipop_share` — какая доля всех кук (до конца текущего дня) смотрела те же объявления. Метки не используются.
   - `te_m`, `te_x` — сглаженная доля ботов среди кук трейна, смотревших эти объявления **в прошлые дни** (target encoding). Используются только метки трейна и только за дни строго раньше, метки теста не используются. Тест длится 7 дней после трейна, поэтому для него разметка отстаёт на 0–6 дней; на трейне это отставание имитируется случайно (`te_lag`), чтобы модель не переоценивала свежесть разметки. Без имитации валидация была завышена (+0.11 вместо +0.08).

## Модель
LightGBM: `learning_rate=0.02, num_leaves=15, min_child_samples=50, subsample=0.8, colsample_bytree=0.8, n_estimators=453`. Финальная модель обучена на всём трейне и усреднена по 5 seed.

## Валидация
Тест лежит позже трейна, поэтому валидация по времени.
- Сначала была одна отложенная часть (~2700 кук). Она оказалась ненадёжной: улучшения на ней не переносились на тест.
- Итоговая схема: **6 временных фолдов** (каждый из последних 6 дней по очереди — валидация, обучение на более ранних), метрика на объединённых предсказаниях (4318 кук, 355 ботов). Шум ±0.04. Новый вариант принимается, только если он лучше предыдущего минимум в 90% ресэмплов **парного бутстрэпа**.

## Результаты
| Версия | Валидация | Тест (Stepik) |
|---|---|---|
| Константа | — | 0.0939 |
| Baseline: 3 счётчика объёма | 0.13 | — |
| v1: поведенческие признаки | 0.70 (1 отрезок) | 0.7764 |
| v2: + последовательности, регуляризация, 5 seed | 0.738 (6 фолдов) | 0.7975 |
| v3: + геометрия курсора | 0.769 (+0.03, лучше в 93%) | 0.8261 |
| **v4: + «толпа» вокруг объявлений** | **0.883 (+0.10, лучше в 100%)** | **0.8901** |

Промежуточные попытки (бленд с CatBoost 0.7883, квартили интервалов 0.7672, сильная регуляризация 0.7897) давали прирост только на одном шумном отрезке валидации и не подтвердились на тесте.

## Что не помогло (6 фолдов)
Квартили интервалов, энтропия секунд и сессии, признаки user-agent и его согласованности с платформой, нормализация платформы, доля дублей и порядок строк, время на странице по типам событий, гистограмма интервалов, география, target encoding по запросам, городам и категориям. Все дали около 0 или ухудшение.

## Выводы и ограничения
- Самые сильные сигналы нашлись не перебором признаков, а **разведкой данных**: сравнением ботов и людей по сырым полям.
- Ботов мало (несколько сотен в валидации), метрика шумная, лишние признаки легко приводят к переобучению.
- Target encoding зависит от свежести разметки: чем дальше тест от трейна, тем слабее сигнал. В продакшене его нужно регулярно пересчитывать.
- Разметка — это трафик нескольких известных сервисов. Новые парсеры с другим пулом объявлений и «человеческим» курсором модель может ловить хуже.
